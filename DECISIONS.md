# Decisions

Calls made during the overhaul without asking, newest last. Each has the reasoning and how to reverse it.

1. **Two production sites.** This repo deploys to two Vercel projects: `field-notes-two-blond.vercel.app` and `field-notes-pwa-gules.vercel.app`. I could not tell which one is installed on the phone, so every release is verified on both. Suggestion: delete whichever project you do not use (Vercel dashboard), so there is one copy.
2. **Tests run in the browser, not Node.** Node is not installed on this machine, and the stack rule is "no new dependencies". `tests/run.html` drives the real app in a frame on a local server. Test mode needs `localhost` plus `?fntest=1` and uses a separate storage key, so it cannot touch real contacts. `tests/` and `tools/` are excluded from deploys by `.vercelignore`.
3. **Full backup is JSON; CSV stays for spreadsheets.** CSV cannot carry ids or reconnect clocks. Restoring a JSON backup replaces the device's data after a confirm and keeps what was there as the rollback copy.
4. **One-step rollback copy.** Before a new version first touches stored data it saves the untouched original under a second storage key. Settings > About > "Go back to that copy" restores it. If storage is full the copy is skipped and the update still runs.
5. **Capture does not log a conversation.** Adding someone starts their reconnect clock from today but does not add an entry to the Log, so Trends is not inflated by captures. Reverse by calling `logInteraction` in `quickAdd`.
6. **Links fill the line but never save.** `?add=Sam+Lee+at+X` opens Add with the text in the box and waits for Enter. A link that writes data by being opened is too easy to trigger by accident. Note for iPhone: a home-screen web app has its own storage, separate from Safari, so links opened in Safari do not reach it. The shortcuts are useful on Android and desktop; on iPhone use the Add tab.
7. **Acquaintance and Networking: listed, never nudged.** The code before v9.6 let a rated Acquaintance reach the reminder card, which contradicted the stated rule. Now the card and the Reach count only consider Close and Middle. Rated people in the other two tiers appear in a folded list at the bottom of the Reach tab, because "an acquaintance I rated Rare" is the product's core case and hiding them entirely would lose it. Reverse by deleting the `further` block in `viewReconnect`.
8. **Promises are for any tier and are not reminders.** A follow-up you typed yourself shows on the Reach tab and in its count until Done. It never produces the card on open.
9. **Penn calendar is built in, with no settings.** 2026-27 dates are from the University calendar (Thanksgiving Nov 26-29, spring classes Jan 20, spring break Mar 6-14). Other years use the usual pattern (fourth Thursday of November, Dec 23 to mid-January, first Saturday of March, May 18 to Aug 23), so they can be a few days off. "Outside Philadelphia" means the person's city is filled in and does not mention Philadelphia or Penn; people with no city are skipped. A prompt with nobody to show does not appear.
10. **Tags live in notes.** `#geoclub` in a person's notes is the tag; there is no tag field, so nothing new has to be filled in and plain search already finds them. Tags are lower-cased when grouped.
11. **Sync against real Upstash is not done, and I did not fake it.** There are no Upstash credentials anywhere I can reach: both production sites return 501 from `/api/sync`, there is no local env file, and the Vercel connector on this machine sees no projects. To finish: Vercel dashboard -> the project your phone uses -> Storage -> Create -> Upstash Redis (free tier) -> connect to the project -> Redeploy. Then `bash tools/sync_smoke.sh https://<your-site>` does a real write, read, conflict and delete with a throwaway record, and the app's sync card can be turned on. Until then sync stays off and the app works fully without it.
12. **Sync conflict rule.** Same person edited on two devices since the last sync: newer copy wins every field, the older copy's notes are appended after " | other device: ", its promise is kept, and its non-empty fields fill any blanks. Histories (conversations, tier changes) are always unioned. Tier itself follows the newer edit; the older tier is still in the tier history. No wire-format change: old and new clients read each other's data.
13. **Rate limit fails open.** If the counter in Upstash errors, the request is allowed. A storage hiccup should not lock you out of your own sync; the size cap still applies.
14. **Penn is worked out, not stored.** Badges come from company, school and email at display time, so the 650-odd existing Penn contacts are labelled without rewriting a single record. A stored `penn` value exists only when you override, and tapping again removes it.
15. **"From Penn" starts on when adding people.** Nearly everyone you meet now is at Penn. Turning it off is remembered until you turn it back on. Typing Penn, UPenn or Wharton switches it on for that one person without changing the default.
16. **Penn is integrated, not a separate section.** One record per person, so nobody can exist twice. "Penn only" gives a Penn-only view of any list and is remembered between opens.
17. **Same-person rule for imports and the Duplicates screen.** Same full name, a shared email, the same first and last name with no conflicting middle, or a shared phone with the same first name (or one first name being the start of the other). A shared phone alone, or a shared last name, never merges people. Checked against the real data: the stricter rule kept apart four numbered entries the first version would have merged.
18. **Importing fills blanks only.** For people already here, an import fills empty fields, adds notes it does not already have, unions logged conversations, and raises potential if the file's is higher. It never changes a tier, a reconnect clock, or anything typed. Undo reverses all of it.
19. **Merging duplicates keeps the closest record.** The one kept has the closest tier (then highest potential, most conversations, most details). Nothing is dropped from the others: notes are joined, histories unioned, blanks filled.
